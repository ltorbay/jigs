Validated workflow: N OpenSpec changes applied in parallel, each in a worktree-isolated subagent producing exactly one commit, cherry-picked sequentially onto main. Only for changes with disjoint file footprints; shared-file changes must be sequenced (check the changes' `tasks.md` file lists first).

**N = 1 is a first-class use.** The value of this skill is the implementer + worktree + main-thread review gate, not the parallelism. With one change: spawn exactly ONE subagent (never a second one "to review" or "to help"), skip the disjointness check, and run every other step unchanged.

**A dependency chain is sequential, not parallel.** A change whose `tasks.md` opens with "confirm X is applied and archived, stop if not" cannot run beside X: it needs X's code AND X's merged spec (its delta may ADD to a spec X creates). Check `openspec/specs/<cap>/` exists for every dependency before spawning; otherwise run apply → review → land → archive → next, one worktree at a time. Shared files (a shared suite, a translation catalogue, root `CLAUDE.md`) make such chains non-parallel even when the precondition is met.

## Gotchas (each one cost real time; do not rediscover)

- **Create the worktree yourself, off a prep commit; do not rely on the tool's built-in worktree isolation.** The built-in worktree forks from the session-start snapshot, so a prep commit made in-session is invisible to it. Recipe: `git worktree add .claude/worktrees/<name> -b apply/<name> <prep-sha>`, then copy any gitignored build artifacts the test run needs (native libraries, export templates), then run the baseline below. Spawn the agent with the path and a pre-flight gate (`git merge-base --is-ancestor <prep-sha> HEAD` and `git branch --show-current` = `apply/<name>`, else STOP). Remove with `git worktree remove --force` (it holds `.godot/` and build output).
- **Baseline runs alone, in the worktree, with a forced import.** Running main's suite (or a second worktree's) while a fresh worktree does its first Godot import produced ~20 spurious failures (`texture_storage.h ... Parameter "t" is null`, `get_height on a null value`) across unrelated suites. One checkout imports at a time; on that signature, rerun with `--import` before diagnosing anything. Put the baseline `[DONE]` line in the brief, plus any known timing flake and the import-flake signature, so the agent reruns instead of diagnosing.
- **Run the suite on main BEFORE spawning and put any pre-existing failure in every agent prompt.** In one nine-agent run a stale spec-index failure existed on the base commit; all nine agents independently burned time diagnosing the same two failures to prove innocence. Fix the baseline first, or name the known failures as expected. With a dirty main (the user's WIP), the worktree baseline is the true one.
- **The test runner scene is the guaranteed conflict point.** New suites use a string `ext_resource` id equal to the suite basename, appended as the last ext_resource and last node, `load_steps` untouched. Conflicts then reduce to a both-keep hunk (2 of 6 changes conflicted in one run; both resolved by deleting the markers).
- **Make the test wrapper's lock per-project-path** (hash of the project dir), so worktree runs do not serialise and any stale-process `pkill` is path-scoped with a trailing-space anchor; give each checkout its own throwaway `$HOME` so `user://` files are per-checkout. Before that hardening, a main-repo run prefix-matched worktree paths and SIGTERMed their in-flight runs.
- **Overlap between a tripwire-widening change and a code-adding change:** resolve the cherry-pick by making the kept code satisfy the widened tripwire, not by allowlisting it.
- **Session limits kill subagents mid-flight.** Resuming an agent by id keeps its context; tell resumed agents to re-verify `tasks.md` checkbox state against actually-landed work before continuing. Resume also survives a removed-and-recreated worktree: say so, with the new base SHA.
- **Shell cwd persists across Bash calls.** After `cd`-ing into a worktree to inspect, cherry-picks run on the wrong branch. Use `git -C <path>`.
- **LSP diagnostics flood with false errors while worktrees exist** (duplicate `class_name` across checkouts). Ignore; the per-worktree suite run is the arbiter.
- **Agents inherit the main-thread model unless overridden; pick the model deliberately.** Measured 2026-10-02 in the source project: the smaller model on a pre-enumerated, low-risk change produced 3 test-quality defects (one vacuous assertion, one over-wide error mute, one unchecked side effect), one fix round, ~400k tokens / 53 min; the larger model on two harder changes produced 0 review defects, caught a wrong design claim and a spec test that could not fail, stopped correctly at a hard gate, and mutation-checked 21 behaviours unprompted, at 327k / 48 min and 418k / 41 min. The cheaper model was not cheaper. Keep the expensive model for the implementer on anything touching timing, concurrency or core loops, and for the main-thread review + cherry-pick gate, which is where judgment pays.
- **The scratchpad dir is shared by every parallel agent.** Two agents both wrote `scratchpad/po.py`; the second overwrote the first, and agent A silently ran agent B's script against its own file. Tell agents to prefix any scratch file with their change name, or to use their worktree's own untracked dir.
- **`openspec/changes/<name>/` dirs are usually untracked; worktrees will not contain them.** Worktrees materialise a commit, not the working tree. Commit the change directories as part of the prep commit (stage explicit paths so the user's other WIP stays out), or every agent stops at a missing `tasks.md`.
- **`design.md` Context was read at an older HEAD.** Every design in one run carried claims the landed code had already changed. List those deltas in the brief under "known differences, already settled" so the agent neither rediscovers them nor trusts the stale text.
- **A task with "stop if" stops the agent with an uncommitted worktree.** Bring the artifact edits back with `git -C <wt> diff -- openspec > patch; git apply patch` on main; annotate the gate task with the outcome and never tick it as passed; waiving it is a user decision recorded in the task text.

## The brief (paste these lines; each one was learned the hard way)

Beyond the gate, the change name, the reading list and the touch-point limits from `proposal.md`, every brief carries:

- **Drift protocol summary** with the exact tasks that pre-authorise design.md / CLAUDE.md / pre-existing-test edits, and: "if an un-enumerated edit of that kind is required, do NOT make it: stop and report with the reason".
- **"No placeholder, tautological or vacuous assertions.** Example of vacuous: a `find(...) < limit` check that passes when `find` returns -1; a check that would also pass with the production line reverted. For anything subtle, revert your production line once and confirm the test fails, and list in the report the tests that are tripwires only."
- **"Do not mute the runner's error capture unless a test deliberately provokes an error, and then only around the single provoking call, never a whole scene build."**
- **"The LAST thing before committing is a full green run with no edit of any kind after it."**
- **Baseline `[DONE]` line, known flakes, "a filtered run is never the gate; each task group ends on a full run".**
- **Known differences since the design was written.**
- **Report format:** SHA + final `[DONE]`, per-group files, every design Context claim that no longer matched, every ambiguity and the choice made, every deviation from `tasks.md` and every drift trigger hit or declined (with the verbatim quoted phrase), added suite wall time, and a mandatory "anything you are unsure is correct" section. The honest-uncertainty section is where the review starts.

## Cloud mode (opt-in only; local worktrees are the default)

Run it only when the user explicitly asks for a cloud run. Implementers move into per-agent cloud containers; **review and cherry-pick stay in the local main thread.** Containers clone the pushed remote, not the session snapshot, so the prep commit (including the normally-untracked change dirs) must be committed AND pushed before spawning; pushing `main` is the user's. A setup script must leave the test wrapper runnable in the container (engine binary plus any native toolchain). Each agent pushes its single-commit branch and re-pushes with `--force-with-lease` after an amend. Gotchas that vanish in cloud: the per-path lock, `$HOME` sharing, scratchpad collisions, the LSP flood. Gotchas that remain: runner-scene id conflicts, pre-existing baseline failures, session limits.

## Sequence

1. Pick independent changes (disjoint task file lists), or exactly one change; check dependency preconditions (archived specs present); commit the prep (change dirs, explicit paths) FIRST and note its SHA.
2. Create each worktree manually off the prep SHA, copy gitignored build artifacts, run the baseline there alone with `--import`.
3. Spawn one agent per change with the brief above and an explicit model choice.
4. **Review pass: the main thread reviews every branch commit itself, BEFORE anything lands.** No reviewer subagents: a spawned reviewer lacks the cross-change context (which files overlap, what the prep commit changed, what the other branches are landing). Per finished branch, read `git -C <worktree> diff <prep-commit>..HEAD` against the change's `tasks.md` + `design.md` and check: diff matches the enumerated tasks (no laundered scope), tripwire suites edited only as tasks pre-declared, project conventions held, no cross-branch collisions, and **every new test read for the "would this pass with the production line reverted" question**.
5. Route CODE fixes through the ORIGINAL agent (context intact): it fixes, amends its single commit, re-runs the suite green. Never patch a worktree from the main thread; the agent's transcript goes stale. DOC-only follow-ups the agent was not authorised to make go straight on main after the pick as their own commit: the pre-archive window sanctions them.
6. Before each cherry-pick, `comm -12 <(git status --short | awk '{print $2}' | sort) <(git diff --name-only <prep> <branch> | sort)` against the user's dirty tree: an overlap means stop and ask, never stash. Cherry-pick one branch at a time, full suite after each. Main-thread conflict resolutions are new unreviewed code; re-read the resolved hunk before the test run.
7. `git worktree remove --force` and delete branches when green. Report what is still open on the change (manual passes, device passes) so the archive is not assumed.
